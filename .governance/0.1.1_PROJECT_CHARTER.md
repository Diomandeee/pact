# PROJECT CHARTER

**Commitment level:** Provisional. Phase zero.

## Purpose

Flow-based infrastructure for prompt and agent systems. You express a system
as a typed flow graph, it simulates, it tells you what is broken, and it
decomposes the chains you already have into a small algebra so you can see
what they actually are.

**In one sentence:** Machinations for agent systems, with decomposition as the
feature.

## The problem it solves

Anyone who has built a serious prompt library arrives at the same place:
dozens of skills, a handful of chains, and no way to answer basic questions
about them. Which of these compose? Which can never fire? Which two are the
same thing wearing different names? What is missing?

Measured on the originating corpus of 150 skills: nine skills can never fire
because nothing produces their input type. Nine of eleven chains do not
typecheck. One type has thirty-three producers and two consumers. Not one
chain implements more than half the canonical cycle.

None of that was knowable by reading the library. All of it was computable in
under a second once the library was expressed as a graph.

## Why it is a product and not a script

The value scales with corpus size, which means it gets more useful exactly
where it is hardest to reason by hand. And decomposition, not composition, is
the differentiator: plenty of tools help you build a chain. Nothing tells you
what the chains you already built actually are.

## Non-goals

**Judging quality.** Type agreement is necessary for a chain to work and
nowhere near sufficient. This finds chains that *cannot* work, which is a
smaller and far more useful set than the ones that might. Any claim to predict
output quality would be false and would poison the credible claims.

**Replacing the agent runtime.** This describes and analyses systems. It does
not host models or manage keys.

**Being a general workflow engine.** The typing is the point. An untyped
version of this is a worse Airflow.

## The mission underneath

Make prompting discussable mathematically and geometrically. Standardise the
vocabulary enough that two people can disagree about a chain and be talking
about the same object.

That is why the glossary is a governance document rather than a README
section, and why every published claim is anchored to a number someone can go
check.

## Success

Phase zero is done when the tool reads the originating corpus, factors every
chain, and reproduces the four Python references exactly. That is the point at
which the analysis stops being a set of scripts and becomes a system.
