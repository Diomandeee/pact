# LIVING CHECKLIST

> Master plan for handoff to an executing agent. Created 2026-07-30.
> Charter: `.governance/0.1.1_PROJECT_CHARTER.md`.
> Invariants: `.governance/0.1.3_ASSUMPTIONS_INVARIANTS.md`.
> Math: `SPEC.md`.
>
> **Every item carries a Gate.** A Gate is a command that either passes or
> fails. No box gets ticked on judgement. INV-6 says no stub passes a gate,
> and the gate script enforces it rather than trusting anyone.

## Objectives (definition of done)

1. Point the tool at a corpus of skills and get back: which chains compose,
   which cannot fire, which types accumulate, and which of the four canonical
   stages each chain is missing.
2. Author a protocol once and validate every graph against it.
3. Simulate a system before running it, and have the simulation predict the
   run.

## Critical path

`L0 engine → L1 algebra → L3 corpus import → L2 analysis → L4 surface`

L2 comes after L3 deliberately. Analysis with no real corpus to analyse is
where a project like this dies: it produces beautiful metrics over synthetic
graphs and never meets a fact that can contradict it.

      **Gate:** `cargo test -p pact-core --test token` — 7/7 passing 2026-07-31.
      Withdraw is all-or-nothing and leaves the source untouched on failure;
      `contains` is reflexive, antisymmetric, transitive; absorb-then-withdraw
      is identity; totals conserved across transfer; a zeroed type is removed
      rather than lingering; iteration order deterministic (INV-3).
- [x] **P1.2** Node vocabulary and both edge kinds.
      **Gate:** `cargo test -p pact-core --test vocabulary` — every `Kind`
      variant constructible with its declared defaults; `Signature::is_lossy`
      agrees with per-type totals; `Rate::resolve` never exceeds availability
      and `appetite` is independent of it; builders are chainable without
      losing earlier settings.
      *(First draft of this gate required a round trip through
      `Graph::validate`, which was circular: `graph.rs` unlocks AFTER P1.2.
      Validation moved to P1.3 where it belongs.)*
- [x] **P1.3** Structural defects: dangling, duplicate, starved, unbounded,
      orphan, sink.
      **Gate:** `cargo test -p pact-core --test defects` — 11/11 passing
      2026-07-31. Three-sided, because the gate as originally written was
      weaker than it looked: "a fixture graph containing all six returns all
      six" is satisfied by a `validate` that returns all six unconditionally.
      So the sides are (1) all six together return exactly six, one of each,
      (2) a clean graph returns none, (3) each defect in isolation returns
      exactly itself. (3) is what kills a detector that fires on the wrong
      shape.
      *(Three real defects found and fixed in `graph.rs` doing this, none of
      them the compile error that was known about: `Kind::Converter` matched
      as a unit variant when it is a struct variant; `Sink` checked only
      pools while its own doc comment said "a defect for anything else", so a

      both invisible; and a duplicated id caused every downstream defect on
      that node to be reported once per copy. Plus one doc-reality
      divergence: the pressure threshold's comment said the number lived in
      `spec/invariants.toml` and it did not. It does now, as
      `pressure_ratio`, with canary SPEC-1 checking the two agree — proved
      to fire by setting them to 3 and 4.)*
- [x] **P1.4** The `Interpreter` trait, and the scheduler written once against
      it.
      **Gate:** `cargo test -p pact-core --test seam` — 18/18 passing
      2026-07-31. The trait's signatures cannot express simulator-only
      assumptions:
        1. no method mentions a seed, a step counter, or a concrete ledger
        2. `transfer` returns `Result`, because an executor's transfer fails
           routinely and a signature that cannot say so cannot be implemented
        3. `available` does not hand back a borrow of an in-memory map
      Cheap, structural, and it catches the leak it names. **Proved to fire**
      rather than assumed: a `reseed(&mut self, seed: u64)` added to the trait
      and `available` changed to return `&u64` both fail the gate, and both
      compile, so the compiler would not have caught either.
      The scheduling rules are tested behaviourally in the same file, because
      they are pure: which node may act is a function of the graph and a
      snapshot, so activation modes, trigger-on-crossing, activator
      conjunction, inhibitor-beats-activator and the per-type conservation
      ledger are all provable here, before any backend exists. P1.5 re-proves
      them end to end.
      *(Two earlier drafts withdrawn. The first required a recording no-op,
      which proves nothing because a no-op needs nothing. The second required
      the same behavioural suite to pass against a hostile implementation,
      which is incoherent: a hostile impl fails transfers by design, so
      behaviour differs on purpose. The expensive proof is building the
      executor, and that is ADR-0004's falsification condition, not a blocker
      at L0.)*

- [x] **P1.5** `Simulator`: activation modes, state edges, delays, gates.
      **Gate:** `cargo test -p pact-core --test simulate` — 20/20 passing
      2026-07-31. Broadcast creates (three copies, one original destroyed,
      books still close), drains destroy, delays release on schedule and hold
      nothing visible meanwhile, inhibitors beat activators in a running
      system, and releasing the brake lets the same system run.
      *(Writing this found **four** defects in the scheduler that had already
      been committed green at P1.4, which is the argument for building the
      second thing rather than declaring the first one done:*
      *1. A source shared one `emits` bag across every outgoing edge, so
      adding a second output doubled the import. Theorem 1 makes import the
      only thing that extends a loop's life, so this was not cosmetic.*
      *2. A converter shared one `produced` bag the same way, emitting twice
      what its signature promised; and it reported the signature rather than
      what it actually emitted, so a converter wired to nothing told the
      ledger it had created resources that did not exist.*
      *3. A pool snapshotted its holdings once and reused it for every
      outgoing edge, so two `Rate::All` edges both claimed the whole pool and
      the second transfer failed against a pool the first had emptied.*
      *4. The big one: an edge whose source pushes and whose target pulls was
      driven from both ends and moved its resources twice. Fixed by a rule,
      not a patch — **storage is pulled from, everything active pushes** —
      so every edge has exactly one owner. A delay needed one more
      distinction on top: its released work is output on its way out, while
      anything else on hand is input waiting to be held, and conflating them
      made a delay fed every step release nothing at all.)*
- [x] **P1.6** **INV-2 conservation**, per type, asserted every step.
      **Gate:** `cargo test -p pact-core --test conservation` — 5/5 passing
      2026-07-31, 1000 generated graphs, zero violations, per type.
      Not circular: the ledger is built from the scheduler's events, so it is
      checked against `Simulator::total_held`, which is read off the backend's
      own maps and never touched by the event stream. Any mutation without an
      event, or event without a mutation, shows up as an imbalance.
      **Proved to fire**: an extra resource added silently inside `copy_to`
      broke 83 of 1000 cases, naming the type and both numbers.
      The suite also asserts the case corpus is alive (event floor, creation
      and destruction both non-zero, every generated type reached), because a
      thousand inert graphs would pass conservation trivially.
      *(This found the last two defects in the scheduler, both over-commitment
      rather than leakage:*
      *1. 137/1000 — two nodes pulling from one passive pool both planned
      against the same start-of-step snapshot, so the second promised
      resources the first had already moved. Fixed with a claim ledger shared
      across the whole step, which also subsumes the case of two edges from
      one pool into one node. A starved plan releases its claims, or it would
      starve every later node for a firing that never happened.*
      *2. 13/1000 — a drain was being pulled from. `pushes()` said a drain
      pushes nothing, which was true and the wrong question: a drain is not
      storage, it destroys what it holds, so anything planning to pull from it
      plans against resources that will not exist. The predicate is now
      `pullable()` and names what may be pulled from — only a passive pool.
      The two are not complements, and writing it the other way round is what
      hid the case.)*
- [x] **P1.7** **INV-3 reproducibility**, same seed same trace.
      **Gate:** `cargo test -p pact-core --test reproducibility` — 5/5 passing
      2026-07-31, 1000 generated graphs, equal under `Eq` **and** byte-identical
      when rendered. Rendering matters separately: two traces can compare equal
      and still render differently if anything in them iterates a set, and the
      rendering is what a human diffs.
      Three checks keep it from being vacuous: a probabilistic graph must route
      differently under two seeds (or the engine is ignoring its seed, which is
      reproducible the way a constant is), a deterministic graph must ignore
      the seed entirely (or something is consulting the PRNG that should not
      be), and two graphs differing by one edge must differ by *adding* to the
      trace while keeping a shared prefix — otherwise every generation looks
      like a total rewrite and the barcode reports births and deaths for
      structures that never changed.

## P2 — L1, the algebra

- [x] **P2.1** The six combinators as types with typed ports.
      **Gate:** `cargo test -p pact-algebra --test combinators` — 20/20
      passing 2026-07-31. `▸` rejects a type mismatch at construction and the
      error names both terms and both types, in its fields and in its
      `Display` (an error that carries the facts in fields and hides them in
      the message has only moved the problem).
      Four-sided, for the reason P1.3 taught: a `sequence` that rejected
      everything would pass the gate as written. So (1) it rejects and names,
      (2) it accepts what composes including `output_type: A | B` alternatives,
      (3) every other combinator's rule is checked the same way, and (4) ports
      propagate through composition and the compiled graph is structurally
      clean and actually runs.
      **Proved to fire in both directions**: making `▸` accept everything fails
      3 tests, making it reject everything fails 9. A one-sided proof would
      have missed the second.
      *Design notes worth keeping:*
      *- `*` is infallible and `↺` is not, and that asymmetry is the point.
      Iteration is one effector repeating its own work, so its ports are
      unchanged by definition. Feedback is the composition returning to its own
      start, which is a claim about types and can be false.*
      *- `↺` refusing to close is the corpus's central gap made mechanical.
      With no `State → M_arch` generator a chain ends holding `State` while its
      first stage reads `M_arch`. That test flips from proving the gap to
      proving it was filled the moment P2.5 lands.*
      *- ⊗ takes the union of branch outputs, not the intersection. A fan-out's
      result is whatever any branch may emit, and intersecting would report a
      fan-out over two differently-typed branches as producing nothing.*
      *- `+` compiles to a splitting gate, not to a condition. The algebra
      carries no predicate to branch on, so round-robin is the honest
      structural stand-in: it routes and does not pretend to know why. A
      protocol needing a real condition attaches a state edge, which is what
      state edges are for. This is stated rather than hidden because it is the
      one place the compilation is weaker than the notation.*
- [x] **P2.2** `Protocol` as a validator over graphs.
      **Gate:** `cargo test -p pact-algebra --test protocols` — 17/17 passing
      2026-07-31. A hand-built straight pipeline is rejected against the `rail`
      protocol, reporting exactly `expands` and no other rule, and the message
      names both what was required (a broadcast gate) and what was found (none).
      **Proved to fire in both directions**: accept-everything fails 9 tests,
      reject-everything fails 5.
      *Design decisions worth keeping:*
      *- A protocol validates a **graph**, not a word. A word is what you
      authored; a graph is what someone HAS. Validating a compiled word would
      prove the compiler, not the validator, so every fixture here is
      hand-built wrong. That is strictly harder and it is the difference
      between a library for people who already agree with the notation and a
      tool for people who do not.*
      *- A `Protocol` is data, a list of `Rule`s, not a trait. Declaring one is
      picking rules; it does not require writing Rust, and a rule list can be
      printed and diffed. A trait would make every protocol a compilation unit,
      which quietly means the only protocols that exist are the ones we ship.
      The closed `Rule` enum is the trade that buys it: inspectable and later
      serialisable, at the cost of a new rule kind being a change to that file.
      If real protocols keep needing rules that are not there, the enum is the
      wrong shape, and that finding is worth more than the inconvenience.*
      *- `Executes` and `Repeats` are different claims, not one. A delay on a
      cycle says an effector repeats; a cycle **through the fan-out** says the
      whole phase does. If `Repeats` accepted any cycle, an inner iteration
      would satisfy it and the outer loop would never have to close, which is
      exactly the gap the live corpus has.*
      *- `WellFormed` covers dangling edges and duplicate ids and deliberately
      NOT starved converters, sinks or orphan sources. The first two mean the
      graph does not describe anything; the rest are diagnoses about a system,
      and every fragment with open ends has them by construction.*
      *- Validation reads shape only, never contents. A rule depending on what
      a pool holds would give different answers at different moments, and a
      check that changes answer mid-run is not a predicate.*
      *(One wrong assertion of mine got a message fixed: I claimed an empty
      graph was vacuously connected. It has zero components, so it does break
      the rule, and the original text "found 0 component(s)" was true and
      useless. It now says "the graph has no nodes". Reporting an empty graph
      as connected would have been technically defensible and practically
      misleading, which is worse than either.)*
- [x] **P2.3** **INV-4**: generator satisfies its own validator.
      **Gate:** `cargo test -p pact-algebra --test witness` — 9/9 passing
      2026-07-31, 1000 generated rule sets. The property as stated: `emit()`
      either **refuses** or produces a graph `validate()` accepts, never a
      third outcome.
      Generated over **rule sets**, not graphs. Random graphs would test the
      validator; random rule sets test the generator against combinations
      nobody designed for, which is where the interactions are — a width cap
      constrains what the fan-out rule may build, and a repeat rule needs that
      fan-out to have somewhere to send work.
      **The circularity trap, and the guard for it.** If `emit` called
      `validate`, INV-4 would hold by construction and the property would
      reduce to "a filter filters", which is true of every filter and
      interesting about none. So `emit`'s body is grepped for any mention of
      the validator. Both halves proved to fire: dropping one edge in the
      generator breaks 460 of 1000 cases, and adding emit-then-check trips the
      guard. The guard catches the obvious version of the mistake, not every
      version — a future author could reach `validate` through a helper — and
      saying which of those two it is costs one sentence.
      Non-vacuity is asserted both ways: more than half the cases must emit
      (or the generator is refusing too much) and at least one must refuse (or
      the refusal half went untested).
      *(A test of mine was wrong and the code was right, which is the first
      time that has happened in this direction. I asserted that
      `GatesBranch{min:3}` with `BoundedWidth{max:1}` is a contradiction. It is
      not: a graph with **no gates** satisfies both vacuously, so the pair
      alone is satisfiable and refusing it would have been the generator
      inventing a conflict that is not there. It becomes a contradiction the
      moment anything forces a gate to exist. Both halves are now tested.)*
- [x] **P2.4** `railpulse` expressed as a word: `↺(⊗ ▸ * ▸ ⊕)`.
      **Gate:** `cargo test -p pact-algebra --test railpulse` — 11/11 passing
      2026-07-31. It renders as exactly `↺(⊗ ▸ * ▸ ⊕)` with 4/4 stages; it
      compiles to a graph its own protocol accepts at every legal width; it
      runs, conserves, and the select stage actually fires; and no crate's
      source names it outside a doc comment.
      Not just outside `pact-core` — outside **every** crate.
      `protocols/railpulse.rs` is pulled in by `#[path]` and compiled into
      nothing that ships. INV-7's reasoning carried all the way out: a
      railpulse inside `pact-algebra` would be privileged over every other
      protocol the *algebra* could host, which is the same failure one layer
      up. A test walks every crate's source to prove it, and a second test
      checks the protocol reaches nothing past the public API, so someone
      else's protocol has exactly the same tools and no fewer.
      *(This gate found **two** real defects, both in code that had already
      shipped green, and one of them is the best find so far.)*
      *1. `⊕` forced its input and output to the same type. That reads fine
      until you try to close a loop: the select stage has to return what the
      fan-out reads, so it is the compaction as well as the merge. A
      same-type-only merge cannot express railpulse at all. `Term::merge` now
      takes `of` and `into`; P2.1's test was updated and still passes 20/20.*
      *2. **The cycle closed on paper and starved in practice.** The test
      written to catch exactly that caught exactly that. Two causes, both
      real:*
      *   (a) `*` compiled the effector straight into its delay and let its
      own exits carry on downstream. A converter SPLITS its output across
      outgoing edges, so the loop arm took all of it and the next stage got
      nothing. `*` now compiles to a splitting gate — repeat-or-continue,
      which is what "repeat until a condition" means when the algebra carries
      no condition.*
      *   (b) With that fixed it still starved, because
      `Distribution::Deterministic` kept its round-robin cursor **local to one
      firing**. A gate fed one resource per step therefore sent every single
      one down the first branch, forever, and `Deterministic` was
      indistinguishable from "always the first" in the commonest case there
      is. Round-robin needs memory and memory lives in the backend, so the
      `Interpreter` gained `rotate(at, outputs)` — an executor implements it
      as "the next worker". Proved load-bearing: freezing the rotation at 0
      fails the gate.*
      *That defect was invisible to every L0 test because they all pushed
      whole batches through a gate in one firing, where a local cursor looks
      exactly like a persistent one.*

- [x] **P3.3** Round-trip: graph → word → graph.
      **Gate:** `cargo test -p pact-corpus --test roundtrip` — 6/6 passing
      2026-07-31.
      *Isomorphic* is stated precisely rather than assumed, because the two
      graphs are deliberately different objects: the imported corpus graph is
      bipartite (types are pools, skills are converters) and a compiled word is
      skill-only. The claim is that **the skill layer survives exactly**: the
      same skills as a multiset of signatures, the same canonical stages, and
      re-factoring the rebuild gives the word we started from. The third is
      what closes the loop — without it the first two are satisfied by a
      rebuild that keeps every piece and loses the structure holding them
      together.
      **Ten of thirteen chains cannot be rebuilt, and that is the correct
      answer.** The algebra refuses to hold an ill-typed word, so a chain that
      does not typecheck has no word to hold. That is the same fact the
      factoring already reported, arriving a second time through an
      independent path. A rebuild that succeeded on a broken chain would mean
      one of the two implementations is lying, and the test asserts the
      refusal names the same break.

- [x] **P3.4** Declared members and shape: `members: [a, (b | c), d]`
      beats the prose scan.
      **Gate:** `cargo test -p pact-corpus --test declared` — 6/6 passing
      2026-11-03, each both directions: a declared list is the word and an
      undeclared chain is still scanned; a declared name that is not a typed
      skill is noted and breaks the chain (the shape that would let a chain
      declare its way to legality); `(a | b)` is one stage and the same two
      names in sequence are two, so a declared sequence of two `M_plan`
      readers whose types do not meet is `✗` where the scan called it `⊗`; a
      declared fan-out whose branches read different types is `✗`. The oracle
      (`decompose.py`) carries the same rule and
      `cargo test -p pact-corpus --test matches_python` agrees on all 13
      chains, every one of which now declares.
      **Proved to fire:** the first run failed four of six, because a
      hand-built skill named `pulse` iterates — the fallback list still
      speaks — and because the refinement case was written against the scan
      (`factor`) rather than the declaration. Both were the tests being wrong
      about the rule, not the rule being wrong; the names moved off the list
      and the case moved to `factor_declared`.
      *The round-trip gate (P3.3) re-factored from the member order under the
      scan's rule, which for a declared chain asks a different question and

- [x] **P4.5** Theorem 1, empirically.
      **Gate:** `cargo test -p pact-analysis --test theorem_one` — 4/4 passing

      generations, against the bound of `2^4 − 1 = 15`.**

      none holding more faces than `2^k − 1`. If a phase could exceed it the
      finiteness argument would be about a different object than the one being
      built.

      is about every loop. It would catch a bound wrong by a lot and miss one
      wrong by a little.*

      external input is not an optimisation — it is the only source of new
      vertices and therefore the only thing that extends a loop's life — so any

      hatch**. P4.4's `admit` could not express import at all: a vertex from

      refused, correctly. The test written for the corollary tried to import
      something and could not. Added `admit_with_import`, where newcomers are
      declared by name. An undeclared newcomer is still a fabrication. The
      difference between import and hallucination is not structural and never
      will be; it is whether someone said so.)*

## P7 — the instrument

The surface reports. This makes it move. Machinations is the reference: a
canvas you wire, a play button, resources you watch flow. The unlock is that
**the corpus already is a Machinations diagram** — types are pools, skills are
converters, and it already simulates and conserves. `M_creative` at 16.5
pressure stops being a number and becomes a pool that visibly fills while
nothing drains it.

**Platform: Rust to WASM, TypeScript canvas.** Not pure TS, because
reimplementing the simulator makes two engines that drift and this project
exists to prevent exactly that. Not HTTP-per-step, because animation needs
60fps and a run is thousands of events. `pact-core` has zero dependencies and
no I/O, so INV-1 accidentally made it the most portable code here;
`wasm-bindgen` lives in a new L4 crate, which is what INV-8 already says.

**Planned with `divergent-rail` and validated by PACT itself.** Four phases,
four tracks each, and the invariant check found a real defect in the plan: three
of the four phases came back with `b₁ = 1`, a dependency cycle with no
deliverable closing it. Each needed a **filling artifact** naming what all
three cycling tracks jointly resolve. With those named, `b₁ → 0` in every
phase, `b₀ = 1` in every phase, `dim ≤ 3` under I2. A prototype at
`prototype/` informed these gates and is not on the map, deliberately: you
cannot write a gate for a medium nobody has seen move.

### P7a — the engine crosses the boundary

- [x] **P7.1** `pact-wasm`: the engine, exposed to JavaScript.
      **Gate:** `cargo test -p pact-wasm --test same_trace` — 4/4 passing
      2026-07-31. A WASM run and a native run are **byte-identical** across
      three seeds and step counts, over a fixture exercising every node kind
      and both edge rates. INV-3 crossing a language boundary.
      **Proved to fire:** offsetting the seed by one inside `run_buffer`
      diverges at byte 8 and names the position, because "they differ" sends
      someone to diff two thousand-line strings by hand.
      *Byte-identical rather than "equivalent" on purpose: equivalence needs a
      comparison function and a comparison function is a place for a difference
      to hide. If the two ever disagree on a rendering detail, that detail is
      exactly the platform dependence this exists to find.*
      *And it compares **one implementation reached two ways**, not two
      implementations that agree today. The crate builds as `cdylib` and
      `rlib`; both call the same `pact_core::Simulator`.*

      buffer: JSON in, JSON out over linear memory, with a thirty-line host in
      raw `WebAssembly`. 275KB of wasm, no npm, no bundler.

      workspace sets `unsafe_code = "forbid"`, which cannot be overridden from
      inside a file — that is the point of `forbid` — so `pact-wasm`'s manifest
      opts out explicitly. An FFI boundary cannot be written without unsafe:
      something has to turn a pointer and a length into a slice. The
      alternative, a byte-at-a-time API to dodge the lint, would be slower,
      longer, and would **hide** the boundary rather than mark it. A new canary

## P8 — reading what isn't typed

Everything PACT knows comes from six frontmatter fields written by hand. A
`SKILL.md` is ~3,000 bytes and the analysis reads about 200 of them. That makes
it a linter for a format only Mohamed uses.

One capability changes that: **a model reads the body and infers the type.**
Point it at a folder of ordinary prompts and every one of the 216 structural
tests applies to input nobody prepared. It is the AI incorporation, the
database, the ingest story and the product at once, which is why it comes
before the seven parked P7 items.

**Why it is not a wrapper.** A model can hallucinate that a skill emits
`M_plan`; it cannot hallucinate that the result *composes*. The composability
analysis shows a bad inference as a dead end immediately. The model supplies
judgment, the engine checks the predicates.

## P9 — the stuck trigger

A measured result from outside the tree: over 7,085 classified human-model
turns, P(next turn is a rejection) is 15% at base, 49% after one rejection,
81% after two consecutive rejections, and 10% after a reframe — below the
shuffled null, so a reframe suppresses rather than resets. That curve is a
two-counter stuck detector, and it is the trigger the live gate needs. The
text-to-move classifier stays in Python behind a process boundary (it is
I/O-bound on the model call; porting it buys nothing). No PyO3: a libpython
link for a prototype bridge is the wrong dependency, and `pact-wasm` could
never use it.

## Rules for whoever executes this

**Port, do not reinvent.** Four verified Python references exist and their
behaviour is pinned by tests:

```
~/.claude/skills/divergent-rail/scripts/loop_harness.py     9/9 homology cases
~/.claude/skills/divergent-rail/scripts/prompt_algebra.py   the category
~/.claude/skills/divergent-rail/scripts/prompt_economy.py   the economy
~/.claude/skills/divergent-rail/scripts/decompose.py        the factoring
```

Every P3 and P4 gate is "matches the Python." That is deliberate: it turns a
rewrite into a differential test, and a rewrite with no oracle is how
behaviour silently changes.

**A gate that cannot fail is not a gate.** Finding 0001 shipped with a
falsification test too weak to have failed, and said so. Do the same: if a
gate could not have caught the thing it claims to catch, write that down
rather than ticking the box.

**Blocked is not failed.** If an item cannot proceed because its boundary does
not exist, name the missing boundary and stop. Do not retry, and do not
substitute a stub to keep moving. INV-6 exists because that substitution is
the single most tempting move in a checklist-driven build.
